# 1.什么是minio

* **MinIO** 是一个开源的对象存储服务器，兼容 Amazon S3 的 API。它可以在本地或私有云中部署，适合存储大规模非结构化数据（如图片、视频、备份等）。

* **S3**（Amazon Simple Storage Service）是亚马逊云（AWS）提供的对象存储服务。它用于存储和检索任意数量的数据，具有高可用性和可扩展性。

* **AWS**（Amazon Web Services）是亚马逊公司提供的云计算服务平台，包含计算、存储、数据库、人工智能等多种云服务。S3 是 AWS 的一部分。

- MinIO 是一个`高性能、轻量级`的`对象存储服务器`，专为**大规模数据存储和分析**而设计。它兼容 `Amazon S3 API`，可以无缝替代 Amazon S3 作为存储后端，并且支持在各种环境中部署，包括物理服务器、虚拟机、容器等。

# 2.文件的存储方式

```bash
OSS，Object Storage Service，对象存储服务
```

* 在开发一个web应用或者客户端程序的时候，我们有多种方式存储图片，视频，办公文档等文件，以下是几种主要的存储方式。

| 存储方式       | 优点                       | 缺点     |
| -------------- | -------------------------- | -------- |
| 服务器磁盘     | 开发便捷，成本低           | 扩展困难 |
| 分布式文件系统 | 实现扩容非常方便           | 复杂度高 |
| 第三方存储     | 开发简单，功能强大，免维护 | 收费     |

* 存储在服务器的磁盘上：实现起来非常简单，但是如果文件越来越多，或者在特定的业务场景下单个文件的内容就很大，就算你的硬盘有 2TB 的空间，服务器的磁盘空间迟早会被占满，而且将文件存储在服务器的硬盘，后期扩展将变得十分麻烦

* 存储在分布式文件系统中：实现扩容非常方便，但相对于直接存储在服务器硬盘上来说，实现也更加复杂

* 第三方存储：国内比较成熟的第三方存储服务有阿里云、腾讯云、七牛云等，缺点当然就是收费

# 3.主流的分布式文件系统

* Fastdfs(国产开源):主备服务，高可用，支持主从文件，支持自定义扩展名，支持动态扩容。
* Minio:性能高，标准硬件条件下MinIO能达到55GB/s的读写,35GB/s的写速率，部署自带管理界面，MinI0.Inc运营的开源项目，社区活跃度高，提供了所有主流开发语言的SDK。

# 4.基本概念

* **Object**

* 定义:存储到MinIO的基本对象，如文件、字节流等

* 特点:具有唯一标识，可设置元数据
* **Bucket**

* 定义:用来存储Object的逻辑空间，相当于顶层文件夹
* 特点:数据隔离，命名唯一，可设置权限
* **Drive**

* 定义:存储数据的磁盘，启动时以参数传入
* 特点:是数据的存储载体，容量有限
* **Set**

* 定义:一组drive的集合
* 特点:分布式部署自动划分，对象存储于其上，Drive数量固定，尽可能分布在不同节点

# 5.架构图

```bash
+-------------------+
|    Client (SDK/   |
|    CLI/Browser)   |
+-------------------+
          |
          v
+-------------------+
|  Load Balancer    |   (可选，提升高可用)
+-------------------+
          |
          v
+-------------------+      +-------------------+      +-------------------+
|   MinIO Node 1    |<---->|   MinIO Node 2    |<---->|   MinIO Node 3    | ...
+-------------------+      +-------------------+      +-------------------+
          |                        |                          |
          +------------------------+--------------------------+
                                   |
                                   v
                        +---------------------------+
                        |   Distributed Storage     |
                        | (本地磁盘/云盘/对象存储)   |
                        +---------------------------+
                                   |
                                   v
                        +---------------------------+
                        |   Distributed Metadata    |
                        |   (Erasure Coding, etc.)  |
                        +---------------------------+
```

- 客户端通过 S3 API 访问 MinIO，可以经过负载均衡器分发请求到不同的 MinIO 节点。
- 多个 MinIO 节点组成分布式集群，节点间通过网络通信，实现数据冗余和高可用。
- 数据和元数据分布在所有节点的本地磁盘上，MinIO 使用 Erasure Coding 技术保证数据安全。
- 整个集群对外表现为一个统一的 S3 兼容存储服务。
