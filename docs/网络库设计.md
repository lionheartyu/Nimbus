# 1. 网络接口层

* 采用 muduo 网络库，负责高并发 TCP 连接管理和事件驱动的异步 IO。

```c++
    // 文件传输服务器 4线程
    EventLoop loop;
    InetAddress addr(8080, "10.20.32.132");
    FileServer server(&loop, addr, "file-server");
    server.start();
    loop.loop();
    return 0;
```

* 定义 `EventLoop` 事件循环对象 `loop`；
* 绑定 IP 地址和端口号，构造 `InetAddress` 对象 `addr`；
* 将 `loop` 和 `addr` 传入 `FileServer` 构造函数，创建服务器实例；
* 调用 `start()` 启动服务器监听；
* 调用 `loop.loop()` 进入事件循环，处理所有网络事件。

---

# 2. muduo 网络库核心设计

- **Reactor 模式**：采用主从 Reactor 线程模型，主线程负责新连接接入，从线程负责 IO 读写和回调处理。
- **非阻塞 IO**：所有 socket 操作均为非阻塞，提升并发性能。
- **事件回调机制**：通过回调函数处理连接建立、消息到达、连接关闭等事件。
- **定时器与任务队列**：支持定时任务和跨线程安全任务投递。

---

# 3. Nimbus 文件服务器网络流程

1. **客户端连接服务器**
    - 服务器监听指定端口，等待客户端连接。
2. **消息收发**
    - 客户端通过 protobuf 协议发送文件操作请求（如上传、下载、列表等）。
    - 服务器解析请求，根据类型分发到对应处理逻辑。
3. **多线程并发处理**
    - 服务器可配置多线程（如 4 线程），每个线程独立处理一部分连接，提升吞吐量。
4. **文件数据传输**
    - 文件内容通过 TCP 流分块传输，支持大文件分片上传和断点续传。
5. **连接关闭与资源回收**
    - 客户端或服务器主动关闭连接时，自动释放相关资源。

---

# 4. 关键类与接口说明

- `EventLoop`：事件循环核心类，负责 IO 事件分发。
- `InetAddress`：封装 IP 地址和端口。
- `TcpServer`：muduo 提供的 TCP 服务器类，支持多线程和回调注册。
- `TcpConnection`：每个客户端连接对应一个对象，管理 socket 读写和生命周期。
- `FileServer`：Nimbus 项目自定义的文件服务器主类，负责协议解析、业务分发和存储交互。

---

# 5. 网络安全与健壮性设计

- 支持超时检测，防止恶意连接长期占用资源。
- 采用 protobuf 协议，避免粘包、拆包问题。
- 对异常和非法请求有详细校验和错误响应，保证服务器稳定运行。

---

# 6. 扩展性说明

- 网络层与业务逻辑解耦，便于后续扩展 RESTful API、WebSocket、gRPC 等接口。
- 支持横向扩展，可通过 Nginx/负载均衡部署多台服务器实例。
